Создал DNS-хостинг.

![Скриншот git.org.ru](/assets/posts/2016/2016-08-01-1-cloudns.ru.png)

Почти каждому проекту рано или поздно нужен собственный домен, а домену -
DNS-зона с записями. Когда таких проектов становится несколько, ручное
редактирование конфигов начинает раздражать. Так появился cloudns.ru -
бесплатный DNS-хостинг, где зонами можно управлять через веб-панель, а не
через текстовый редактор.

## Задача

Сформулировал я её так: пользователь заводит домен, добавляет записи A, AAAA,
CNAME, MX, TXT, NS - и всё это должно работать без поддержки "с руками из
плеч". То есть система должна сама превращать записи из базы данных в рабочие
зоны на DNS-сервере. Админка - только лишний источник ошибок, значит важно
было сделать понятный интерфейс и по возможности убрать лишние шаги.

## Стек

В 2012-2013 году я выбирал какой стек выбрать - мой стек был C# и perl - я
выбирал что-то новое для меня.

Выбор пал на проверенный минимум, который мне показался перспективным:

- **php+twig+peeweeidiorm** - сама веб-панель. Фреймворк лёгкий, для такого
  сервиса большего и не нужно;
- **postgresql** - основная база данных: пользователи, домены, записи;
- **bind9** - сам DNS-сервер, король в этой области.

## Сложности

Самое коварное в DNS - это кеширование на всех уровнях. Поменял запись -
а по всему миру она ещё сутки живёт в кешах. Поэтому:

- TTL выставляется с умом: для «горячих» зон меньше, для стабильных - больше;
- генератор зон тщательно экранирует данные: в zone-файл нельзя пускать
  пользовательский ввод без проверки - иначе сломается вся зона;
- reload вместо restart - чтобы не ронять обслуживание зон при каждом
  изменении.

## Возможности

- Неограниченное количество DNS-зон
- Поддержка записей A, AAAA, CNAME, MX, SRV, TXT, NS
- Неограниченное количество записей
- Уведомление об истечении срока регистрации домена
- Уведомление об изменениях зон
- Управление сервисом через API

## Что получилось

Сервис закрывает главную потребность: бесплатно держать DNS своих проектов и
управлять им через панель.
